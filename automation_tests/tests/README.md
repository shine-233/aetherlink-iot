# API 自动化用例

本目录保存基于 Mocha 的 API 自动化、覆盖率契约、预检契约和业务能力闭环检查。

## 目录定位

- 面向认证、设备、遥测、告警、配置、系统、角色权限、字典、OTA、自动化场景、MQTT 管线等 HTTP API。
- 与 `lib/` 中的覆盖率和报告模块配合，生成端点命中、业务证据、边界证据和阻塞原因。
- 这里的用例必须用真实响应、状态变化或负向场景证明行为，不能只证明请求发出过。

## 文件用途

- `00_*` 多为契约、预检、覆盖率或环境规则检查。
- 编号业务文件验证对应领域 API。
- `helpers/` 保存可复用夹具和辅助断言。
- 新增文件会被 `run_tests.js` 自动发现，不需要手工注册到运行器。

## 验证命令

```powershell
cd automation_tests
npm run test:list
node run_tests.js --module 00_coverage_contract --list
```

执行真实 API 自动化前必须确保后端和测试数据存在；本次目录标准化不运行 broad API 套件。

## 审查发现

- 宽泛状态码、空列表接受、跳过用例和包装器调用都可能让覆盖率看起来比业务闭环更强。
- 如果测试元数据缺失，报告只能靠文件名或分类器推断证据类型，可信度较低。
- 边界冒烟和目录契约有价值，但不能被提升为业务正确性证明。

## 重构/清理建议

- 新增或修改用例时写清楚证明的业务能力、前置数据和负向场景。
- 跳过必须说明具体缺少的账号、设备、数据或服务。
- 优先补精确 body/state/user-visible 断言，再提高覆盖率数字。
