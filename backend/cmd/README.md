# 后端命令目录说明

`backend/cmd` 是后端工作区的命令入口目录，承载生成工具、本地模拟工具和自动化支持命令。

## 目录职责

- 提供独立可执行入口，避免把工具逻辑混入业务服务启动流程。
- 汇总后端生成、联调和自动化相关命令，便于维护者按场景查找。
- 作为运行边界，帮助区分手写逻辑、生成逻辑和本地辅助脚本。

## 文件关系

- `gen/` 负责 GORM 生成入口，输出查询层和模型代码。
- `virtual_sensor/` 负责虚拟传感器启动、MQTT 客户端和 payload 生成。
- `aetherlink-device-autotest/` 负责设备自动化测试支撑，虽然不在本次修改范围内，但属于同一命令目录体系。

## 重点文件

- `gen/main.go`：数据库表到代码的生成入口。
- `virtual_sensor/main.go`：虚拟传感器进程入口。
- `virtual_sensor/mqtt_client.go`：MQTT 连接与重连封装。
- `virtual_sensor/temp_hum_sensor.go`：模拟遥测、属性、事件和网关消息的核心逻辑。

## 当前静态审查结论

- 该目录中的命令大多依赖本地配置、broker、数据库和生成输出路径，运行前需要明确环境前提。
- 生成类命令有覆盖现有文件的风险，尤其是输出目录和表清单配置。
- 虚拟设备类命令容易把 broker 地址、账号和设备 ID 写死在源码里，存在环境泄露风险。

## 改进方案

- 把路径、broker、账号和表名抽成配置或命令参数，减少硬编码。
- 为生成命令补充更严格的生成前检查，避免误覆盖手写代码。
- 为虚拟传感器补充环境说明和 topic 约定，减少联调时的协议偏差。

## 建议实施步骤

1. 先确认每个命令的运行环境是否具备本地数据库或 MQTT broker。
2. 再确认生成命令的输出目录是否允许被覆盖。
3. 最后把环境变量、topic 约定和生成范围补入对应目录 README。

## 预期效果

- 目录职责更清晰，后续维护者更容易定位入口。
- 降低误运行、误覆盖和误泄露配置的风险。
- 让命令类目录具备更稳定的静态审查依据。

## 静态审查重点

- 是否存在硬编码配置需要迁移到环境变量或本地配置文件。
- 是否存在生成命令覆盖手写代码的可能。
- 是否明确说明了各命令所需的本地依赖。
