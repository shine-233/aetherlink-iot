# 代码生成目录说明

`backend/cmd/gen` 是后端 GORM 代码生成入口，负责把数据库表结构转换为 `internal/query` 下的查询代码和模型代码。

## 目录职责

- 提供单独的生成命令入口，避免把生成逻辑混入业务启动流程。
- 根据数据库连接和表名列表生成指定数据表的 model/query 代码。
- 作为生成资产的变更边界，帮助区分手写代码和工具生成代码。

## 文件关系

- `main.go` 是唯一执行入口，负责初始化配置、数据库连接和生成器。
- `main.go` 中的表名列表决定本次会刷新哪些生成结果。
- 生成结果默认写入 `../../internal/query`，与后端查询层直接关联。

## 重点文件

- `main.go`：最关键的生成控制点，包含配置路径、数据库初始化和生成表清单。

## 当前静态审查结论

- 该目录本身不包含复杂业务逻辑，主要风险来自生成范围配置错误。
- `main.go` 中的表名如果维护不严，容易出现生成结果与仓库现有文件不一致的问题。
- 输出目录如果调整不当，可能覆盖到错误位置，或者让生成物散落到不可预期的路径。

## 改进方案

- 将生成目标表、输出目录和配置文件路径集中成常量或命令参数，降低误改风险。
- 在生成前增加人工检查清单，确认数据库结构、输出路径和受影响文件范围。
- 为生成结果增加更清晰的目录级说明，避免后续维护时误删或误改生成文件。

## 建议实施步骤

1. 先确认本次生成只针对 `device_templates` 相关结构。
2. 再确认 `../../internal/query` 是预期输出目录。
3. 最后执行生成前的静态审查，核对仓库中现有生成文件是否允许被覆盖。

## 预期效果

- 让生成入口更容易被维护者理解。
- 降低误生成、误覆盖和误删除生成文件的概率。
- 方便后续把生成流程纳入规范化检查。

## 静态审查重点

- 生成表清单是否与当前数据库结构一致。
- 输出路径是否仍然指向仓库内预期目录。
- 配置文件路径是否适用于当前本地或 CI 环境。
