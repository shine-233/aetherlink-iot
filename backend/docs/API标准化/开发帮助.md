# API 标准化开发帮助

本说明用于帮助后端开发者在 **AetherLink IoT** 当前代码树中定位 API 相关代码，而不是描述旧项目骨架。

## 当前相关目录

```text
backend/
├── main.go
├── configs/
├── docs/
├── internal/
│   ├── api/          # HTTP 处理器
│   ├── middleware/   # 中间件
│   ├── service/      # 业务服务
│   ├── dal/          # 数据访问层
│   ├── model/        # 数据模型
│   └── query/        # GORM Gen 查询代码
├── pkg/
│   ├── errcode/      # 错误码与错误封装
│   ├── common/
│   └── utils/
└── router/
    ├── apps/         # 各业务模块路由挂载
    ├── router_init.go
    └── sse.go
```

## API 开发建议

1. 路由注册放在 `router/apps/` 或 `router/router_init.go`。
2. HTTP 请求处理放在 `internal/api/`。
3. 业务逻辑放在 `internal/service/`。
4. 数据访问逻辑放在 `internal/dal/`、`internal/query/`、`internal/model/`。
5. 错误码、统一错误返回和通用工具优先复用 `pkg/errcode/`、`pkg/common/`、`pkg/utils/`。

## 配置与文案

- 运行时配置位于 `backend/configs/`。
- 当前常见配置文件包括 `conf.yml`、`conf-dev.yml`、`conf.example.yml`、`messages.yaml`、`messages_str.yaml`。
- 本地私有覆盖应放在被 Git 忽略的 `conf-localdev.yml` 或环境变量中。

## 与生成文件相关的注意事项

- `internal/model/*.gen.go` 与 `internal/query/*.gen.go` 属于生成文件。
- 修改或删除前，请先阅读 `../../cmd/gen/README.md` 和根目录 `../../../GENERATED_FILES.md`。

## 一条简单的分层规则

保持调用方向稳定：

`router -> internal/api -> internal/service -> dal/query/model`

不要把业务规则重新塞回路由层或零散工具函数里。
