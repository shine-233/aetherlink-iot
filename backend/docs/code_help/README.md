# 后端代码辅助文档

## 目录定位

本目录汇总后端代码结构、Go 编码规范、AI 辅助开发说明和开发标准，帮助维护者以一致方式阅读、扩展和审查后端代码。

## 文件说明

- `directory_structure.md`：后端目录结构与模块职责。
- `golang_standards.md`：Go 代码风格、错误处理、测试和工程约定。
- `AI_code.md`：AI 辅助开发时的使用边界和注意事项。
- `development_standards/`：注释、日志和命名等细分开发规范。

## 文件关系

`directory_structure.md` 负责“去哪找代码”，`golang_standards.md` 负责“如何写代码”，`development_standards/` 负责“具体细节怎么统一”。当源码目录调整时，应优先更新目录结构说明。

## 审查记录与重构建议

- 问题描述：规范文档如果不跟随代码演进，会变成历史说明，反而误导新维护者。
- 改进方案：把规范更新纳入代码审查清单，涉及目录、日志、命名、注释的大改动必须同步文档。
- 实施步骤：为每次结构性改动记录对应文档更新点，并在发布前做一次规范与源码路径核对。
- 预期效果：降低新成员理解成本，减少风格漂移。

## 验证建议

- 修改规范后抽样检查当前代码是否符合新规则。
- 如果规范暂时无法落地，应在文档中标注迁移计划，而不是直接宣称已完成。
