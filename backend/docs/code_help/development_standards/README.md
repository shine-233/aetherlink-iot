# 后端开发标准

## 目录定位

本目录保存后端开发的细分标准，当前覆盖注释、日志输出和命名约定。它服务于代码审查、文档化和 GitHub 发布前标准化。

## 文件说明

- `comment_standards(注释规范).md`：说明文件注释、函数注释和复杂逻辑注释的写法。
- `logs_standards(日志输出规范).md`：说明日志级别、上下文、敏感信息和排障可读性要求。
- `naming_notations(命名规范).md`：说明包名、文件名、变量、函数和领域对象命名规范。

## 审查记录与重构建议

- 问题描述：注释、日志和命名常常在多人维护后变得不一致，影响排障和代码搜索。
- 改进方案：把本目录作为后端 PR 审查标准来源，新增或重构代码时同步检查三类规范。
- 实施步骤：先按高风险模块补齐文件级说明，再逐步统一日志字段和命名词汇。
- 预期效果：提升可读性、搜索性和问题定位效率。

## 验证建议

- 文档更新后抽查 `backend/internal/service`、`backend/internal/api`、`backend/mqtt` 等高频目录。
- 涉及日志规范时，确认不会输出密码、Token、密钥或完整敏感 payload。
