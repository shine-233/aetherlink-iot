# 后端业务设计文档

## 目录定位

本目录保存后端业务设计材料，用于解释功能背景、数据字段含义、流程约束和历史设计决策。它是理解业务意图的辅助资料，不替代当前源码、测试和运行验证。

## 文件说明

- `automated_scene_linkage.md`：自动化场景联动设计说明。
- `users-table额外扩展字段需求&设计.md`：用户表扩展字段需求与设计说明。
- `在线离线.md`：设备在线/离线状态相关设计说明。

## 文件关系

设计文档应与 `backend/internal/service/`、`backend/internal/model/`、`backend/internal/dal/`、`backend/mqtt/` 和相关数据库迁移保持一致。发现设计与当前实现不一致时，应在文档中标注状态，而不是静默保留过期结论。

## 审查记录与重构建议

- 问题描述：历史设计文档容易与实现漂移，尤其是自动化、在线离线和用户扩展字段这类跨模块功能。
- 改进方案：为每篇设计文档增加“适用版本/当前状态/相关源码/验证方式”章节。
- 实施步骤：先补目录 README，再逐篇核对当前实现和测试证据，标注已实现、已偏离或待验证。
- 预期效果：让维护者能快速判断文档是否仍可作为开发依据。

## 验证建议

- 修改设计文档后抽查对应源码和测试是否支持文档结论。
- 对自动化和在线离线这类运行时功能，最终仍需要 API、MQTT 和数据库层面的联调证据。
