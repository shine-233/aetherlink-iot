## 一、SNMPv3 点表契约（device_configs.protocol_config）

SNMP 点表在 v2c 四键（`target`/`community`/`timeout_ms`/`points`）基础上新增五个可选键：

| 键 | 含义 | 校验 |
| --- | --- | --- |
| `v3_user` | SNMPv3 用户名 | 非空即走 v3 路径（`v3_user` 为空时其余 v3 键不得出现） |
| `auth_proto` | 认证协议 | `md5` / `sha`（大小写与 `hmac-md5`/`hmac-sha` 别名可解析，经 `snmp.AuthProtocolByName`） |
| `auth_passphrase` | 认证口令 | 必填（v3 模式），≥8 字符（RFC 3414 §11.2 取强制口径） |
| `priv_proto` | 隐私协议 | 仅 `none`/空（authPriv 加密未实现，其余值保存即拒） |
| `priv_passphrase` | 隐私口令 | 仅当 priv 启用时可填（当前 priv 恒关，填写即拒） |

关键约定：

1. **fail-closed**：`community` 在 v2c 路径仍必填；v3 路径（`v3_user` 非空）下 `community`
   缺省并被忽略。校验在 `pointconfig.ParseSnmpConfig` 单点完成，保存链路
   （`service.validateCollectorProtocolConfig` → `device_config` 创建/更新）与采集链路
   （`collector.SnmpPoller.Poll`）共用同一解析器——保存通过的点表采集器必然可解析。
2. **前端契约**：v3 字段为动态表单键（`internal/service/collector_form.go` 的
   `v3_user`/`auth_proto`/`auth_passphrase` 三个元素），前端
   `views/device/config-detail/modules/form.vue` 按 `dataKey` 通用渲染，无需前端特判；
   `priv_proto`/`priv_passphrase` 暂不进表单（能力未实现，避免表单承诺兑现不了的能力）。
3. **明文口径**：v3 口令与 v2c `community` 同为 `protocol_config` 明文存储，仅限受信内网
   （与平台 MQTT 明文门禁口径一致）；`auth_passphrase` ≥8 字符为保存期强制约束。

## 二、SNMPv3 客户端（internal/snmp/v3.go）

- 报文层：RFC 3412 封装（version=3 / msgGlobalData / msgSecurityParameters / scopedPDU），
  认证 GetRequest 按 RFC 3414「摘要段零化后计算 HMAC-96、再回填真实摘要」组装。
- 引擎发现：首次 Get 前发送 noAuthNoPriv 可上报探测，从响应 `msgSecurityParameters`
  取回权威 engineID/boots/time（兼容 Report/GetResponse 两种承载），随后以该 engineID
  完成 `PasswordToKey → LocalizeKey` 本地化密钥派生。engineID 不落配置。
- 边界：仅实现 authNoPriv；密钥派生沿用 `usm.go` 既有自洽口径（与外网标准 agent 的
  互操作属运行时边界，见 `usm_test.go` 头注——本仓测试以内嵌 v3 agent 双侧同源验证闭环）。
- 采集语义：与 v2c 一致——每次采集独立 UDP 事务（连接即用即弃），客户端不跨轮保持
  引擎状态；discovery 与请求各占用一次 `timeout_ms`/Runner 预算（最坏 2×timeout）。

## 三、LwM2M 多客户端隔离（internal/protocolgw + internal/lwm2m + internal/coap）

原拓扑为共享单 ObjectStore + 「最近一次 /rd 注册」last-wins 端点归因，多客户端并发时
遥测会串户。现拓扑：

1. **注册/去注册事件挂接**：`lwm2m.Registry.HandleRegisterWithEvents` 在 POST /rd
   （新建或刷新）触发 `EventRegister`、DELETE /rd/{id} 触发 `EventDeregister`，事件携带
   端点名、注册 ID 与 UDP 源地址（去注册端点在注销前查得）。
2. **per-endpoint store**：`TelemetryBridge` 维护 端点→ObjectStore 与 源地址→端点
   两个 `sync.Map`；注册为端点建独享 store（幂等，刷新注册不清空已写资源），去注册
   移除 store 与全部指向该端点的地址绑定。
3. **按源路由**：`coap.Message` 新增 `RemoteAddr`（仅 `Server.servePacket` 出站填充，
   不进入线上编码）；`isolatedObjectRouter` 把 /3303* 对象读写按源地址路由到该端点
   独享 store，未注册源一律 4.04（fail-closed）。端点归因在写入事件入队时固写，
   消费侧不再读取任何「当前端点」状态——多客户端并发写入互不串扰。
4. **无 bridge 降级**：未装配遥测桥（DB/uplink 未就绪）时保持原共享 store 纯接入层形态。
5. **连带修复**：protocolgw 原以精确路径挂载 `/rd`，`DELETE /rd/{id}` 到达不了处理器
   （去注册 404）；现改挂 `/rd*` 前缀（与 `internal/lwm2m` 库自测用法一致）。

## 四、验证与残留边界

已验证：见「验证方式」一节的 Go 单测清单；全仓 `go build ./...` 通过。

残留边界（如实口径，后续迭代）：

1. DTLS-PSK / DTLS 会话（需 pion/dtls 依赖与真实握手环境）。
2. observe 服务端订阅生效（`internal/coap/blockwise_observe.go` 仍为纯组件）。
3. authPriv 加密（priv_proto 仅 none）。
4. SNMPv3 与外网标准 agent 的互操作联调（依赖真实 agent 环境）。
5. 队列模式（Queue Mode）未实现。
