# 【功能级】设备在线状态管理概要设计

> 本文按当前源码做静态对账（checked-at：2026-08-04）。它说明实现边界，不等于已经在目标部署环境完成 Redis/PostgreSQL 运行验收。

## 1. 当前数据与配置

- Redis 使用设备维度的过期 key：`device:{deviceId}:heartbeat` 和
  `device:{deviceId}:timeout`。
- 设备配置使用 `heartbeat` 与 `online_timeout`（秒）决定优先级和过期策略；
  当前服务实现优先处理 `heartbeat`，两者同时配置的约束由设备配置服务校验。
- PostgreSQL `devices` 表持久化 `is_online` 与 `last_offline_time` 等状态字段。
- MQTT/上行处理在收到已识别设备消息后刷新对应 Redis key；过期监控器消费
  Redis 过期事件并把设备标记为离线。

## 2. 关键流程

1. 上行消息解析出设备身份和设备配置。
2. 心跳模式刷新 `device:{deviceId}:heartbeat`；在线超时模式刷新
   `device:{deviceId}:timeout`。
3. 设备从离线变为在线时更新持久化状态；重复消息只刷新 TTL，不重复制造状态事件。
4. Redis 过期事件经过设备 ID/key 格式校验后，更新 `devices.is_online` 和离线时间。

## 3. 历史字段边界

旧设计中的 `heartbeat_time`、`timeout` 不是当前已确认的 PostgreSQL 权威字段。
如果未来要把它们落地，必须先补迁移、model、读写方、恢复/并发语义和验证记录，
不能仅凭本文件添加列或把旧示例当作当前 schema。
