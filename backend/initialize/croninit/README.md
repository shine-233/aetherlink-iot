# croninit 目录说明

本目录负责注册后端启动后持续运行的真实定时任务，是 `backend/initialize` 下与后台调度最直接相关的实现目录。

## 职责

- 提供统一的 cron 调度器实例和启动入口。
- 注册自动化执行、系统清理、脚本执行、消息清理等周期任务。
- 承载设备状态统计这类需要周期采集并写入 Redis 的后台作业。

## 关系

- `cron.go` 是定时任务总入口，负责把各类任务挂入全局调度器并启动。
- `device_stats.go` 是 `cron.go` 依赖的具体子任务实现之一。
- 上层通常通过 `backend/initialize` 的启动链路间接触发本目录，而不会单独初始化子任务。

## 审查结论

- 该目录的主要风险来自“任务注册入口集中、执行依赖外部服务且长期驻留”。
- 当前生产使用路径以 `cron.go` 为准，新增任务时优先挂到这里的全局调度器入口。
- 本次只补充说明文档和源码注释，不改 cron 表达式、任务顺序或调度器生命周期。

## 方案

- 在 README 中固化职责边界、入口关系和审查注意点。
- 为关键任务入口和统计任务补充说明性注释，帮助维护者快速识别副作用来源。
- 明确说明停止入口和 Redis 统计键的用途，方便后续排查。

## 步骤

1. 核对全局调度器的注册入口和启动方式。
2. 核对设备统计任务的执行频率、键格式和数据保留时长。
3. 以目录 README 记录职责、关系、审查结论和预期收益。

## 预期效果

- 审查者能更快识别哪些改动会影响后台周期任务。
- 维护者在新增任务或调整频率前，更容易定位已有入口和停止方式。
- 在不动业务代码的前提下，提高该目录的可读性和运行副作用透明度。
