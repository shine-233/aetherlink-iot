# 后端逻辑辅助层

`backend/internal/logic` 保存一些不适合直接放在 `api/`、`dal/` 或 `service/` 中的领域辅助逻辑。

这里适合放可复用、相对纯粹的逻辑片段，但不适合长期承载租户、权限或副作用敏感的核心业务规则。

## 目录职责

- 提供可复用的领域辅助逻辑或纯函数。
- 服务于上层业务编排，但尽量不直接依赖 HTTP、数据库或运行时装配细节。
- 作为“可复用逻辑收纳层”，而不是“业务主流程主战场”。

## 维护边界

- 需要权限判断、租户隔离或副作用触发的逻辑，应优先留在 `internal/service`。
- 若某段逻辑已经和具体存储、接口或设备链路强耦合，就不应继续留在这里伪装成“纯逻辑”。

## 审查与重构建议

### 发现的问题

- 逻辑辅助层如果边界不清，容易和 `service/` 重复承载相似规则。
- 一旦职责漂移，后续会同时出现“service 里有一份、logic 里也有一份”的维护风险。

### 改进方案

- 保持这里只有高复用、低副作用、相对纯粹的逻辑。
- 一旦发现权限敏感或流程编排逻辑滑入这里，应及时回迁到 `service/`。

### 预期效果

- 目录职责更清晰，后续抽纯函数或补聚焦测试时更容易定位。
- 减少业务规则漂移和重复实现。
