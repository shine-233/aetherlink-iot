# 后端中间件层

`backend/internal/middleware` 保存 AetherLink IoT 后端请求链上的 HTTP 中间件，包括认证、授权、请求处理以及历史兼容响应链等横切逻辑。

中间件目录虽然文件数量不一定多，但影响范围通常是全局的，因此一处看似很小的改动也可能改变权限、日志、上下文注入或响应行为。

## 目录职责

- 在请求进入业务 handler 前处理认证、授权和上下文准备。
- 承担部分横切能力，例如兼容响应包装或公共请求链行为。
- 为 API 层和 Service 层提供稳定的请求上下文基础，而不是承载业务规则本体。

## 当前关注点

- `response/`
  - 保存旧响应链相关实现和说明，已在本轮补充中文边界文档。
- 其他认证、授权类中间件
  - 任何逻辑变动都可能影响全局访问控制，需要谨慎处理。

## 审查与重构建议

### 发现的问题

- 中间件改动天然是全局影响面，容易放大到所有 API。
- 历史兼容中间件如果文档不足，后续维护者容易误判它是不是主链路的一部分。

### 改进方案

- 继续明确每个中间件会修改哪些上下文、哪些响应、哪些权限边界。
- 对兼容响应链、认证和授权类中间件建立更清晰的 README 与文件头说明。
- 后续如需重构，优先先补验证清单，再做小步收敛。

### 预期效果

- 全局请求链更容易审查，也更方便定位权限或响应回归。
- GitHub 浏览者能快速理解这里是“横切控制层”，不是普通工具目录。
