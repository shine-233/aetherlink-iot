# 响应兼容中间件

`backend/internal/middleware/response` 保存旧响应链或兼容响应包装逻辑，用于在部分历史接口或调用路径中维持既有响应行为。

## 目录职责

- 处理兼容响应包装或历史响应链相关逻辑。
- 作为主响应路径之外的兼容层，而不是默认业务响应出口。

## 维护边界

- 这里的逻辑若被误当成主链路，后续很容易扩大兼容债务。
- 修改响应结构、错误文案或包装方式后，需要同步核对前端和自动化对响应的依赖。

## 审查建议

- 问题：兼容响应链最容易因为“先留着”而长期模糊职责。
- 改进：在 README 和代码注释里持续强调它的兼容层定位，并收集后续收敛机会。
- 预期效果：维护者能快速判断某段响应逻辑是否还值得保留，避免继续扩大历史包袱。
