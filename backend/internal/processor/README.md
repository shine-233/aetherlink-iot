# 后端处理管线

`backend/internal/processor` 保存后端侧的数据处理管线，用于承接设备数据、业务事件或内部处理任务的转换与串联。

这类目录通常不直接对外暴露接口，但会深度影响数据进入业务系统后的形态和后续副作用，因此属于“改动不多、风险不低”的区域。

## 目录职责

- 处理设备或业务数据的中间转换流程。
- 承接 API、MQTT、上下行链路之外的内部处理阶段。
- 为上层服务提供更稳定的数据加工能力。

## 审查与重构建议

- 问题：处理管线容易把输入输出转换逻辑藏得很深，API 层很难直接看出它改了什么。
- 改进方案：补清输入输出形态、关键转换规则和副作用边界，必要时再补聚焦 fixture 验证。
- 预期效果：后续调整处理规则时，更容易判断影响面，也更容易定位回归。
