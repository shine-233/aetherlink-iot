## 一、为什么要做这一条

P0.1 的证据文档里写着一句容易被忽略的话：

> 全新空库 `aetherlink_migrate_20260912` 用项目自身 `initialize.CheckVersion` 顺序跑
> `sql/1.sql…93.sql`（`AETHERLINK_TIMESCALE_MODE=off`）→ `MIGRATE_OK` / `sys_version=93` / 114 张表
> （**注：该验证只到 93，94–99 未做同等全链验证**）。

而迁移当时已经到 109。也就是说：

> **发布门禁里最基础的那一条——"全新库能装上"——有 16 个迁移从未在干净库上跑过。**

这恰好是"最贵的失败方式"：功能缺失用户能忍，"装不上"直接出局。而且这 16 个迁移
**全部处于未提交状态**，一旦其中任何一个在空库上失败，问题会在交付现场才暴露。

## 二、新增工具：`backend/cmd/migchaincheck`

不另写一套执行器，而是**直接调用项目自身的 `initialize.CheckVersion`**——
与生产启动完全同一条代码路径。自己实现一个执行器是这里最容易犯的错：
"校验通过"和"生产走的是另一条路"会同时成立，而后者没人验过。

三个设计点：

| 设计 | 理由 |
| --- | --- |
| **拒绝非空库**（除非 `-allow-dirty`） | 在非空库上跑只能验证"增量升级"，验证不了"从零安装"。这正是本次要验的东西 |
| 核对 `sys_version` 落点与建表数 | "跑完了"与"跑对了"是两回事；迁移被静默跳过时命令照样返回 0 |
| 退出码 2 表示**环境不满足** | 沿用 P0.1 既有契约：**绝不把"没验证"写成"通过"** |

## 三、实测结果

```bash
# 1) 建全新空库
psql -h 127.0.0.1 -p 55433 -U postgres -d postgres \
  -c "CREATE DATABASE aetherlink_migchain_20260917;"

# 2) 跑全链（工作目录必须是 backend/，CheckVersion 按相对路径读 sql/<n>.sql）
cd backend
AETHERLINK_TIMESCALE_MODE=off go run ./cmd/migchaincheck \
  -dsn "host=127.0.0.1 port=55433 user=postgres password=x dbname=aetherlink_migchain_20260917 sslmode=disable"
```

```
目标程序版本 VERSION_NUMBER=109，VERSION=...
空库校验：现有业务表 0 张
...（依次执行 sql/1.sql … sql/109.sql）...
升级成功

迁移完成：耗时 837ms
sys_version      = 109（期望 109）
public 表数量     = 126

VERDICT=PASS :: 全新空库全链迁移通过
```

**结论：1 → 109 全链在全新空库上通过，`sys_version` 与 `VERSION_NUMBER` 一致，建表 126 张。**

### 3.1 负向对照：空库守卫不是摆设

对**刚刚被填充**的同一个库再跑一次：

```
目标库不是空库（已有 125 张业务表）。在非空库上跑只能验证增量升级，验证不了从零安装。
请改用新建的空库，或显式加 -allow-dirty。
EXIT=2
```

守卫按预期拒绝。没有这条对照，"它拒绝非空库"就只是注释里的一句话。

### 3.2 提交态与工作区的区分（重要）

| | `VERSION_NUMBER` | `sql/` 最大编号 | 一致性 | 本次验证 |
| --- | --- | --- | --- | --- |
| **已提交（HEAD）** | 103 | 103 | ✓ | 覆盖（94–103 属本次区间） |
| **工作区** | 109 | 109 | ✓ | **✓ 已实测** |

本次验证的是**工作区**（109）。104–109 这 6 个迁移目前仍是**未提交状态**，
本次实测证明了它们**能在一张白纸上干净应用**——但它们的"已提交性"仍需其作者收尾。

## 五、仍未闭环（如实记录）

1. **本工具尚未接入 `scripts/roadmap/preflight-release.ps1`**。它目前是手动执行的，
   而门禁的价值在于自动化——建议把它作为 preflight 的一个步骤，
   在 `-CheckOnly` 之外的完整模式里用一个临时空库实跑。
2. **TimescaleDB 路径未验**：本次用 `AETHERLINK_TIMESCALE_MODE=off`（与本地栈一致），
   57.sql 的 hypertable 转换被跳过。开启 Timescale 的全链未验证。
3. **只验"装得上"，不验"装对了"**：126 张表说明结构建起来了，
   但没有逐表核对列、索引、约束与预期一致（那是另一类验证）。
4. 空库是一次性的（`aetherlink_migchain_20260917`），**用完应删除**，避免占库。
