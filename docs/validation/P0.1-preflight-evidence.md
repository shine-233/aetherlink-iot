## 实现要点

- **迁移上界一致性**：比对 `backend/pkg/global/global.go` 的 `VERSION_NUMBER` 与
  `backend/sql/` 下最大编号迁移。这是 AGENTS.md 明令要求、且不需要数据库即可验证的不变量。
- **打包文档在位**：`deploy/package.sh|ps1` 按文件名打包 `README.md`、`START-HERE.md`、
  `VALIDATION.md`、`SECURITY.md`、`THIRD_PARTY_NOTICES.md`，缺一份即部署包不完整。
- **工作树状态**：脏树只 WARN 不阻断（避免共享开发树恒定失败），但必须显式标注快照未证明。
- **环境探针**：无目标 / 不可达一律 PENDING（退出码 2）。**绝不把"没验证"写成"通过"**。

## 2026-09-12：门禁抓到一个真实缺陷（VERSION_NUMBER 落后于迁移文件）

修复提交 `b8450d8`。

**发现过程**：并行会话新增了 `backend/sql/89.sql`，但 `global.go` 的 `VERSION_NUMBER` 仍是 88。
`pg_init.go` 的迁移循环上界就是 `VERSION_NUMBER`，因此 **89 永远不会被执行**——
全新部署会静默停在 88，缺表缺约束且不报错。这正是 AGENTS.md 要求核对的那条不变量。

门禁实跑输出（发现时）：

```
[FAIL] migration-ceiling :: VERSION_NUMBER=88 but max migration=89
VERDICT=BLOCKED :: 1 static invariant(s) failed
EXITCODE=1
```

修复 `VERSION_NUMBER = 89` 后复跑：

```
[PASS] migration-ceiling :: VERSION_NUMBER=89 matches max migration=89
[PASS] release-docs :: packaging docs present: ...
VERDICT=PENDING :: static invariants pass, 3 live check(s) not executed
EXITCODE=2
```

并额外验证**迁移 89 本身兼容全新库**：新建空库跑完整链，`MIGRATE_OK`，`sys_version = 89`。
（仅改上界不够——必须确认被跳过的那个迁移文件本身能跑通。）

这条记录是"门禁真能拦住问题"的实例：一个不报错、静默少跑迁移的缺陷，
在它进入主干前被静态检查拦下。

## backup-restore.ps1 实跑（五场景）

真实能力是**清单生成与完整性校验**（不需要数据库），dump/restore 执行缺工具即 PENDING。

```
=== manifest ===            [PASS] manifest-write :: 2 file(s) hashed   EXITCODE=0
=== verify-clean ===        [PASS] manifest-verify :: 2 file(s) match    EXITCODE=0
=== verify-tampered ===     [FAIL] manifest-verify :: hash mismatch: a.sql  VERDICT=BLOCKED  EXITCODE=1
=== plan (no tooling) ===   [PENDING] tooling-pg_dump / tooling-psql / backup-dsn  EXITCODE=2
=== plan-root-path ===      [FAIL] artifact-path :: refusing a filesystem root  VERDICT=BLOCKED  EXITCODE=1
```

关键点：篡改一个字节即被 SHA-256 清单检出并阻断；**缺 `pg_dump`/`psql`/DSN 时一律 PENDING，
不把"没执行"写成"备份成功"**；`backup` / `restore` 两个动作明确 PENDING 而不是伪造执行。

## 过程中修掉的缺陷

1. **`[CmdletBinding()]` 与 `param()` 之间插注释导致解析失败** —— 注释必须放在特性之前。
2. **行尾管道符换行** —— Windows PowerShell 5.1 不支持（PS7 才支持），需改为显式循环。
3. **中文注释 + PS 5.1 默认按 ANSI 读脚本** 的编码风险 —— 已按仓库既有风格改为纯 ASCII 英文。
4. **`git` 不可用时脚本直接崩溃** —— 改为检测命令存在性后报 PENDING，符合 fail-closed 契约。
5. **`Write-Output` 污染函数返回值** —— `Test-TargetPresent` 用 `return $true/$false` 判断，
   但函数内 Pend 的输出会一起进入返回值，导致"无目标"也被判为有目标并继续跑。
   改为脚本级标志 `$script:HasTarget`。
6. **`$Host` 不能作参数名** —— 是 PowerShell 内置变量。
7. **同一个 `Write-Output` 坑在 backup-restore 里又犯了一次** —— `Test-ArtifactPathSafe`
   用返回值判断，FAIL 行被吞掉，且根目录被当成"安全"继续遍历 C 盘。已改为脚本级标志。
   这条值得当成写这类脚本的硬规则：**判断函数一律用脚本级标志，不要用返回值**。
8. **子进程隔离不可行** —— 脚本 `exit 1` 会终止会话导致后续语句不执行；
   想用 `Start-Process` 隔离被安全策略拦下（且提示可能递归强删）。只能逐场景单独跑。
