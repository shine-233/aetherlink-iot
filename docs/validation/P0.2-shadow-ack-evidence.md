P0.2 此前记录为「源码层完成；运行时证据待统一验证」。本轮**补齐了数据库层的运行期证据**；
按 ROADMAP §4，因仍缺真实 MQTT 端到端与浏览器证据，**P0.2 整体仍不得记为 done**。

## 为什么这条不变式值得单独验证

旧实现 dispatch 成功即写 `delivered`，等于**把"已下发"当成"设备已确认"**——
这是路线图里点名的虚假成功。迁移 84 引入 `sent` 态与 `ack_at` 修正了这点，
但没有运行期证据就无法确认修正真的生效。本轮用例直接断言：

1. 下发后状态必须是 `sent`，不是 `delivered`；
2. ACK 后才是 `delivered`，且 `ack_at` 非空（不能用 `delivered_at` 顶替——前者是确认时间，后者是送达时间）。

## 过程中的一个坑

`device_shadow_messages.id` 与 `device_id` 都是 `uuid` 类型。
用自定义字符串（如 `shadow-<时间戳>`）会直接报：

```
invalid input syntax for type uuid (SQLSTATE 22P02)
```

必须用真 UUID（仓库用 `github.com/go-basic/uuid` 的 `uuid.New()`）。
