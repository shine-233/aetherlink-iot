P0.5 此前记录为「仅导入校验层有可运行证据」。本轮补齐**清理执行路径**的数据库层证据；
按 ROADMAP §4，因缺浏览器 E2E，**整体仍记为 partial 而非 done**。

## 与既有单元测试的区别

`device_preregister_cleanup_test.go` 用**注入的 ops** 验证语义（load/classify/remove 均可替换）；
本份走**真实的 load → classify → remove**，验证删除真的按分流结果落到数据库，
而不是只在注入替身上成立。两者互补，缺一不可：
只有注入测试无法证明真实删除生效，只有真实删除测试则无法隔离语义。

## 过程中踩的两个坑

1. **`devices.product_id` 有外键 `fk_product_id`** —— 直接插设备会报
   `violates foreign key constraint (SQLSTATE 23503)`，必须先写入 products 记录。
2. **gorm gen 的查询对象必须 `query.SetDefault(db)`** —— 只设 `global.DB = db` 不够，
   `query.Device` 仍是 nil，一调用就空指针 panic。报堆栈在 `buildPreRegisterExportQuery`，
   但根因在测试初始化，不在被测代码。

## 边界

1. 单条清理路径的数据库行为；导出面（Excel 脱敏）未在本次验证（其脱敏由
   `device_preregister_export.go` 的 MaskVoucher 保证）。
2. 单次运行（`-count=1`），未做多轮稳定性验证。
3. 使用的是临时实例上的临时库，未触碰主实例 5432。
