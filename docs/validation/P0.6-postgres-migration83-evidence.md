# P0.6 迁移 83 的 PostgreSQL 运行期证据

日期：2026-09-11
环境：Windows / go1.26.2 windows-amd64 / PostgreSQL 17.5（本地临时实例）

## 结论

| 项 | 状态 | 依据 |
| --- | --- | --- |
| 迁移 83 的 schema、约束与状态词表 | **有运行期证据** | `TestReportMigration83Postgres` 实跑全 PASS（44.655s） |
| 并发 slot 唯一性、claim 唯一归属 | **有运行期证据** | `competing_materializers_keep_one_scheduled_slot`、`competing_claimers_have_one_owner` PASS |
| fencing token 过期不可续租/结算 | **有运行期证据** | `stale_generation_fence_cannot_renew_or_settle`、两组 `expired_*_loses_every_settlement_before_reap` PASS |
| generation 成功与 delivery outbox 原子性 | **有运行期证据** | `generation_success_and_delivery_insertion_are_atomic` PASS |
| ambiguous 收口、软删除保留历史、幂等冲突 | **有运行期证据** | 对应子用例全部 PASS |
| 真实浏览器 / 活栈 API 端到端 | **仍缺** | 需要运行中的平台与浏览器 |

此前 `docs/validation/P0.6-P0.7-evidence.md` 记录这些为"因缺 DSN 被 SKIP"，
**本轮已解除该阻塞**：并发/fencing/ambiguous/outbox 原子性不再缺运行期证据。
**但 P0.6 整体仍不得记为 done**，因为仍缺活栈 API 与浏览器端到端证据（ROADMAP §4）。

## 环境如何搭起来的（可复现）

本机此前被认为"无可用 PostgreSQL"，实际是主实例要求密码（scram-sha-256），
而仓库配置里只有占位符 `CHANGE_ME_DEV_DB_PASSWORD`。实际可用路径：

1. 本机装有 PostgreSQL 17（`C:\Program Files\PostgreSQL\17`），主实例在 5432。
2. 用户目录下存在 7 月建的验证用数据目录 `C:\Users\Zz\al_pg_verify`，
   其 `pg_hba.conf` 为 **trust**，且同为 PG 17。
3. 用该数据目录在空闲端口起临时实例（仅监听回环）：

```
pg_ctl -D "C:\Users\Zz\al_pg_verify" -o "-p 55432 -c listen_addresses=127.0.0.1" -l <logfile> -W start
pg_isready -h 127.0.0.1 -p 55432
psql -h 127.0.0.1 -p 55432 -U postgres -c "CREATE DATABASE aetherlink_m83_test;"
```

4. 执行测试：

```
cd backend
set AETHERLINK_TEST_PSQL_DSN=postgres://postgres@127.0.0.1:55432/aetherlink_m83_test?sslmode=disable
go test ./internal/dal/ -run TestReportMigration83Postgres -count=1 -v
```

该用例每个子测试自建 `report83_<uuid>` schema 并在 cleanup 中 `DROP SCHEMA ... CASCADE`，
**不污染目标库**，可重复执行。

## 边界与清理

- 仅单次运行（`-count=1`），未做多轮稳定性验证。
- 使用的是 7 月的验证数据目录，**不是** 生产或主实例数据；未修改主实例 5432 的任何内容。
- 临时实例在 55432 监听回环地址；停止命令：
  `pg_ctl -D "C:\Users\Zz\al_pg_verify" stop -m fast`
- 未向仓库写入任何验证脚手架（数据目录与实例均在仓库外）。
