## 最关键的断言方式

不是"调用了加密函数"就算数，而是**直接读数据库列**来断言：

```go
stored := storedAPIKey(t, db, row.ID)      // SELECT api_key FROM ai_models WHERE id = ?
if strings.Contains(stored, plain) { ... } // 库里绝不能出现明文
if !secrets.IsEnvelope(stored) { ... }     // 必须是信封格式
```

只断言"调用成功"无法发现降级为明文落库的情况；必须落到存储层看真实值。

## 实现要点

1. 主密钥经 viper 读取（`secrets.active_key_id` + `secrets.master_keys.<keyID>`），
   测试用例注入临时密钥后**必须清理**——viper 是全局的，会污染同进程其他用例。
2. 明文先经 `sealModelAPIKey`（`secrets.Seal(plain, tenantID)`，AAD 绑定租户）再落库，
   因此把 A 租户密文当 B 租户解必然失败，无法冒充可用凭证。
3. 出参经 `aiModelMasked` 只出掩码；解密失败时传空串，不回显密文或明文片段。
4. 迁移窗口内遗留明文行仍可读，但必须标记 `needsReseal=true`，供自愈式轮换使用。

## 边界

1. 仅覆盖数据库层；生产环境主密钥应通过环境变量注入，配置文件中不得出现真实密钥——
   这一点未在本次验证范围内。
2. 单次运行（`-count=1`），未做多轮稳定性验证。
3. 使用的是临时实例上的临时库，未触碰主实例 5432。
