## 本轮新增

文件：`backend/internal/service/rule_chain_version.go` + 同名测试。

语义要点：

- 版本沿 `draft -> published` **单向推进**；published 只读、不可重复发布。
  允许改已发布版本等于让线上正在跑的图被静默替换且无法追溯。
- **回滚产生新草稿，不回写原版本**（沿用本项目 OTA 批次回滚的既有约定
  `RollbackFleetCommandJob`），原历史保持只读，两侧各留一条审计事件。
- 版本号单调递增，由已有最大版本推导，**不接受外部传入**，避免跳号撞号。
- **图哈希参与版本身份**：内容未变不产生新版本，否则每次保存都堆一个空版本，
  把"改了什么"稀释掉。
- 非法流转（重复发布、归档后发布、回滚目标非 published、空标识）一律 fail closed。

## 2026-09-12 追加：端点已接线（提交 1e2add7 + 接线提交）

迁移 93.sql 建 `rule_chain_versions` 表并登记三个新路由，随后完成 model/dal/service/api/router 接线：

```
GET  /api/v1/rule-chains/:id/versions       列出版本
POST /api/v1/rule-chains/:id/versions       新建草稿（图哈希未变不产生空版本）
POST /api/v1/rule-chains/versions/publish   发布（draft -> published，仅一次）
POST /api/v1/rule-chains/versions/rollback  回滚（造新 draft，不改写历史）
```

设计要点：

- 持久化编排**一律复用纯语义函数**，不另写一份状态机（避免两份规则漂移）。
  编排函数因此带 `Record` 后缀——**Go 没有重载**，与纯函数同名会直接编译失败。
- 发布用 DAL 带条件更新（`status='draft'`），影响行数 0 判为「已发布」并报错，
  **不静默成功**——并发重复发布静默成功等于让状态机形同虚设。
- 「一条链同时只能有一个 published」交给**数据库部分唯一索引**，
  不做应用层先查再写（高并发必漏判）。
- 租户一律取 `claims.TenantID`，不接受请求体指定。
