# Materials 工作区包

`frontend/packages/materials` 保存共享 UI materials、布局辅助和可复用界面片段，用于减少页面重复实现。

## 目录定位

- 提供跨页面复用的 UI 片段、布局辅助或物料定义。
- 支撑页面壳层、配置面板、表格操作区等常见组合。
- 将稳定的 UI 结构沉淀为可维护的共享包。

## 关键关系

- materials 被多个页面复用，样式或 props 变更可能影响不同业务场景。
- 布局辅助通常和响应式断点、主题 token、组件库版本有关。
- 若 materials 被可视化编辑器或页面生成逻辑引用，需同时关注序列化/注册契约。

## 维护注意事项

- 不要把单页面强业务逻辑下沉到共享 materials。
- 新增 material 时要说明适用场景、必需 props 和不适用边界。
- 修改布局能力后要检查桌面和移动端基础显示。
- 保持导出面克制，避免共享包变成杂物箱。

## 代码审查与重构建议

- 问题：共享 UI 包如果缺少边界，会让页面依赖变重且难以替换。
- 改进方案：按“展示物料”“布局辅助”“业务桥接”分层，业务桥接尽量留在 src 侧。
- 实施步骤：先梳理现有导出和调用方，再补组件说明/示例，最后移除长期未使用的 material。
- 预期效果：页面复用更清晰，UI 调整影响面更容易评估。
