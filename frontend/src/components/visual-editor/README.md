# 可视化编辑器组件

`frontend/src/components/visual-editor` 承载可视化编辑器外壳、配置桥、状态管理和类型支持，影响仪表盘编辑、组件配置和数据源绑定。

## 目录定位

- 提供可视化编辑器的组件容器、配置区和共享状态。
- 连接 ThingsVis/内部可视化能力与前端业务页面。
- 保存 widget 配置、导入导出、数据源映射等编辑器相关契约。

## 关键关系

- 配置桥与 `configuration` 子目录共同决定 widget 配置如何读取、编辑和持久化。
- 状态管理影响编辑器撤销、保存、预览、导入导出等流程。
- 类型定义需要和实际持久化 JSON 保持兼容，否则历史仪表盘可能无法恢复。
- 可视化页面和业务设备数据源之间存在跨模块依赖，变更时要同时看数据绑定链路。

## 维护注意事项

- 不要直接破坏历史 widget 配置字段，必须提供兼容读取或迁移策略。
- 新增配置项时要说明默认值、序列化格式和旧数据 fallback。
- 导入导出路径必须保持稳定，避免只在新建场景验证成功。
- 涉及 iframe、外部可视化平台或 token 传递时，要同时检查安全边界和兼容键。

## 代码审查与重构建议

- 问题：编辑器状态、配置桥和持久化格式耦合较强，容易出现“新配置能保存、旧配置打不开”的回归。
- 改进方案：为配置 schema 增加版本说明和迁移函数，把 UI 状态与持久化数据分层。
- 实施步骤：先梳理现有 widget 配置字段，再补默认值/迁移测试，最后验证导入、编辑、保存、回显闭环。
- 预期效果：可视化配置演进更安全，历史仪表盘兼容性更可控。
