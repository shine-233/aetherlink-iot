# 前端国际化资源

`frontend/src/locales` 保存前端 i18n 消息、语言包入口和本地化辅助逻辑，影响菜单、路由标题、表单文案、按钮提示与部分自动化断言。

## 目录定位

- 维护中文、英文等界面文案与 key 结构。
- 为页面、组件、store、请求头语言标识提供统一翻译能力。
- 承接路由菜单、业务表单、告警提示、可视化配置区等用户可见文本。

## 关键关系

- 菜单和路由标题通常依赖固定 key，改名会影响导航显示。
- 自动化测试和 E2E 可能依赖可见文案，文案重命名需要同步测试期望。
- 请求层语言头与当前 locale 应保持一致，否则后端错误消息语言可能和 UI 不一致。
- 新增业务模块时，应先确定 key 命名空间，避免把文案散落在通用区域。

## 维护注意事项

- 不要删除仍被路由、菜单、表单或自动化引用的 key。
- 批量重命名 key 时，要用 `rg` 全局确认引用面，并同步迁移测试。
- 面向用户的中文应保持自然易懂，避免保留机器翻译或乱码。
- 若文案来自后端枚举，应记录枚举来源和 fallback 逻辑。

## 代码审查与重构建议

- 问题：国际化 key 变动容易表现为运行时缺字、菜单空白或测试断言失败。
- 改进方案：为高频 key 建立命名约定，并增加缺失 key 的开发期提示。
- 实施步骤：先扫描未使用/重复 key，再按模块整理命名空间，最后把路由、菜单、自动化断言一起验证。
- 预期效果：文案维护更稳定，新增页面时更容易找到正确命名空间，跨语言发布风险降低。
