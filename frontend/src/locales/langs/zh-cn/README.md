# 中文语言包

## 目录职责

本目录保存简体中文界面文案，通常是理解业务语义、核对字段含义和补齐其他语言包的主要参考。前端在 `zh-cn` 语言环境下会读取这些 JSON 文件展示页面内容。

## 文件关系

目录内 JSON 文件按业务域拆分，并应与 `en-us`、`es-es`、`fr-fr` 中的同名文件保持结构一致。新增中文文案后，需要同步补齐其他语言包的同路径 key，避免语言切换时出现缺失。

## 重点文件

- `common.json`：通用按钮、提示、状态和基础交互文案。
- `route.json`：中文菜单和页面标题，需要与路由配置保持一致。
- `device_template.json`：物模型页面文案，是设备接入、模型定义和物模型测试功能的重要语义来源。
- `visual-editor.json`：可视化编辑器文案，影响看板搭建体验。
- `rdi.json`：RDI 相关业务文案，需与正式需求和验收材料保持一致。

## 审查建议

- 问题描述：中文语言包常被当作事实源使用，如果命名不统一，会把不一致扩散到英文、西班牙语和法语语言包。
- 改进方案：将中文文案与产品术语表、README、接口文档同步维护，明确设备、告警、自动化、遥测、RDI 等核心概念的标准叫法。
- 实施步骤：先整理高频术语；再逐文件检查同义不同名问题；最后通过语言包键一致性脚本确保新增 key 已同步到其他语言。
- 预期效果：降低翻译歧义，提高文档、界面和测试用例之间的语义一致性。

## 使用注意

- 不要把临时调试文案、测试文案或未确认的产品名写入正式语言包。
- 修改中文 key 的名称会影响所有语言和调用方，应优先只改 value。
- 删除文案前先用 `rg` 搜索 key，确认没有页面、组件或测试仍在使用。
