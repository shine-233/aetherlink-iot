# 前端插件注册

`frontend/src/plugins` 负责应用启动时的 Vue 插件注册，是 router、store、i18n、UI 组件库和全局 provider 生效的启动入口之一。

## 目录定位

- 集中注册第三方插件、本地插件和全局 UI 能力。
- 保持应用启动流程显式可读，避免插件初始化散落在页面或业务组件中。
- 为全局 provider、指令、图标、主题、国际化等能力建立固定加载顺序。

## 关键关系

- 插件顺序会影响 router guard、Pinia store、i18n 翻译函数和 UI provider 是否可用。
- 全局组件或指令变更会影响大量页面，不能只看单个入口文件。
- 和 `frontend/src/store`、`frontend/src/router`、`frontend/src/locales` 的初始化顺序存在隐式依赖。

## 维护注意事项

- 新增插件时必须说明为什么需要全局注册，能局部注册的能力优先局部化。
- 不要在插件初始化阶段执行重型业务请求，避免拖慢首屏或引入启动竞态。
- 插件内不要读取未初始化的 store/router/i18n 实例。
- 修改启动顺序后，应做应用启动 smoke、登录跳转和语言切换 focused 验证。

## 代码审查与重构建议

- 问题：插件注册错误通常表现为大面积运行时异常，定位成本高。
- 改进方案：把插件列表、顺序和副作用写清楚，并为关键 provider 增加启动期断言或 smoke 测试。
- 实施步骤：先梳理当前插件依赖，再拆分纯注册逻辑和带副作用初始化，最后补充启动入口验证。
- 预期效果：应用启动链路更透明，插件升级和替换更安全。
