# 路由守卫目录

## 目录职责

本目录负责注册前端全局路由守卫，集中处理权限校验、动态路由初始化、页面标题、导航进度条和移动端布局判断。它是用户进入业务页面前的关键控制层。

## 文件关系

- `index.ts`：统一注册所有路由守卫，决定守卫挂载顺序。
- `permission.ts`：权限守卫，负责登录态、角色权限、外链路由、动态路由初始化和 403/登录跳转。
- `progress.ts`：导航进度条守卫，在路由切换前后调用 `NProgress`。
- `title.ts`：页面标题守卫，根据路由元信息、登录子路径和系统名称生成浏览器标题。
- `mobile.ts`：移动端布局守卫，用于判断当前路由是否适合移动端布局。
- `__tests__/`：守卫行为测试，保护权限跳转和移动端布局判断等关键分支。

## 重点文件

- `permission.ts`：风险最高，任何 `next()` 调用顺序或条件判断错误都可能造成白屏、重复导航、越权访问或错误重定向。
- `mobile.ts`：移动端适配入口，需特别注意排除登录页、错误页和显式禁用移动布局的路由。
- `index.ts`：守卫注册顺序入口，新增守卫前必须确认不会与权限守卫重复消费导航控制权。

## 审查建议

- 问题描述：权限守卫同时处理登录态、动态路由、外链和角色判断，条件分支较多，后续修改容易引入重复 `next()` 或漏跳转问题。
- 改进方案：把纯判断逻辑抽为可测试函数，例如登录重定向判断、角色权限判断、not-found 动态路由恢复判断。
- 实施步骤：先用现有测试锁定未登录、已登录、外链、无权限、not-found 恢复等分支；再逐步抽函数；最后保留 `permission.ts` 作为薄编排层。
- 预期效果：降低路由守卫维护成本，让权限策略变更更容易用单元测试验证。

## 使用注意

- 新增守卫时优先放在 `index.ts` 中统一注册，不要在业务页面里散落注册全局守卫。
- 权限守卫中每条分支应确保只调用一次 `next()`，并在跳转后及时 `return`。
- 修改路由元信息字段时，需要同步检查 `permission.ts`、`title.ts`、菜单生成逻辑和相关测试。
