# 前端请求客户端

`frontend/src/service/request` 负责前端统一 HTTP 请求客户端，是页面、状态仓库与业务 API wrapper 之间的公共入口。

## 目录定位

- 统一选择接口基础地址、开发代理与运行时请求路径。
- 注入认证 token、租户/语言等公共请求头。
- 规范化 query/body 参数，并集中处理后端响应 envelope、401、业务错误提示与网络异常。
- 为 `frontend/src/service/api` 下的业务请求提供稳定的底层能力。

## 关键关系

- 登录态来自 store 或本地缓存，请求层只读取并注入，不应自己决定登录流程。
- 国际化语言头需要和 `frontend/src/locales`、后端语言识别策略保持一致。
- 401/鉴权失败会影响路由跳转和会话清理，变更时必须同步检查 router 与 auth store。
- 响应解包规则会影响所有 API wrapper，不能只验证单个页面。

## 维护注意事项

- 不要在业务页面里绕过统一 request client 直接写散落的 `fetch` 或临时 axios 实例。
- 新增拦截器时要明确执行顺序，避免 token、语言头或错误提示被后续拦截器覆盖。
- 不要在此目录写死本地地址、账号、租户或调试 token；本地差异应通过环境变量或开发代理处理。
- 修改错误处理后，至少做登录失效、普通业务错误、网络失败三类 focused 验证。

## 代码审查与重构建议

- 问题：请求层属于全局横切逻辑，小改动会影响几乎所有页面和自动化用例。
- 改进方案：把响应 envelope、错误码、重试、401 清理、语言头注入等契约拆成可测试的小函数。
- 实施步骤：先为现有行为补单元测试，再逐步抽离纯函数，最后用少量页面 smoke 验证真实调用链。
- 预期效果：全局 API 行为更可预测，登录/API 故障排查成本更低，发布前回归范围更清楚。
