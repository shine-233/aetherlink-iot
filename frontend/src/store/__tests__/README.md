# 全局状态单元测试

## 目录定位

本目录属于 AetherLink IoT 前端的 全局状态单元测试 范围，用于集中维护该能力的源码、测试或静态资产。目录内文件应保持职责清晰，避免把跨领域逻辑直接写入局部组件。

## 主要文件/资产

- `app.test.ts`: 本目录内的主要文件或资产，需要与 全局状态单元测试 的职责保持一致。
- `auth.test.ts`: 本目录内的主要文件或资产，需要与 全局状态单元测试 的职责保持一致。
- `route.test.ts`: 本目录内的主要文件或资产，需要与 全局状态单元测试 的职责保持一致。
- `tab.test.ts`: 本目录内的主要文件或资产，需要与 全局状态单元测试 的职责保持一致。

## 依赖关系

依赖 Vitest、Vue Test Utils、模块 mock 和被测目录的公开接口；测试数据应尽量贴近真实业务契约。

## 审查发现

审查重点是测试是否只证明不报错，还是覆盖了用户可见结果、错误分支和权限/状态边界。

## 测试覆盖目标

- 覆盖 全局状态单元测试 的公开行为、关键状态变化、错误/空数据分支和回归风险。
- 测试应优先断言用户可见结果、服务请求参数、store 状态变化或路由结果，避免只断言组件成功挂载。

## 当前缺口

- 仍需定期核对被测目录是否新增入口，避免测试只覆盖旧路径。
- 若测试依赖 mock，需要确认 mock 与真实接口契约同步，防止形成虚假覆盖。


## 重构建议

建议沉淀共享 fixture 与 mock 工具，把重复挂载逻辑抽出，并为负向/异常路径补充用例。

## 验证建议

运行对应测试文件的 Vitest，并配合 `pnpm exec eslint <测试目录> --quiet` 做语法与规则检查。
