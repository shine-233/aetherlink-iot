# 前端类型声明

`frontend/src/typings` 保存前端全局类型、领域模型类型和声明补充，是 TypeScript 静态检查的基础设施目录。

## 目录定位

- 定义应用级、路由级、组件级、API 级和业务领域级类型。
- 为第三方库、自动导入、全局变量或生成声明提供补充类型。
- 支撑 service、store、views、components 之间的数据契约。

## 关键关系

- 全局声明会影响整个前端类型检查，错误扩散面比普通业务文件更大。
- API 类型应尽量和后端响应结构、mock 数据、自动化断言保持一致。
- 生成型声明要和生成脚本、依赖版本、CI 校验保持同步。
- 新业务优先放在局部领域类型中，确认复用后再提升为全局类型。

## 维护注意事项

- 不要用过宽的 `any` 或全局接口掩盖真实数据差异。
- 修改全局声明后，需要运行前端 typecheck；若暂时不能运行，应在状态文档里明确验证缺口。
- 生成文件不要手工维护业务含义，变更应回到生成源。
- 类型命名应体现业务上下文，避免 `Data`、`Info` 这类难以追踪的泛名继续扩散。

## 代码审查与重构建议

- 问题：宽泛声明会让 TypeScript 失去保护能力，后续 bug 可能到运行时才暴露。
- 改进方案：按领域拆分类型边界，减少全局污染，并把 API envelope 与业务 payload 分开描述。
- 实施步骤：先找出使用面最广的声明，再补充真实字段说明和测试样例，最后逐步收紧 `any`。
- 预期效果：类型错误更早暴露，业务模块之间的数据契约更清楚。
