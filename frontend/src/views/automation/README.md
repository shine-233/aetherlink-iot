# 自动化视图目录

## 目录定位

`frontend/src/views/automation` 是自动化场景和联动规则的前端页面集合，面向 GitHub 维护者时可以理解为“规则编排 UI”的入口。这里负责把用户选择的触发条件、设备指标、配置指标、执行动作和场景状态转换成后端自动化规则契约。

本目录的风险点不在静态展示，而在表单状态和 payload 转换：字段默认值、条件组合、设备/指标选择和启停删除等操作都可能影响真实自动化规则。

## 关键文件与子目录关系

- `scene-manage/` 是场景管理页面，负责场景列表、创建、编辑、启停和删除等入口。
- `scene-linkage/` 是场景联动列表/配置入口，`scene-linkage/modules/dataList.vue` 承载局部列表展示和操作。
- `scene-edit/` 是场景编辑页面，负责把场景表单转换为后端可保存的数据结构。
- `linkage-edit/` 是联动规则编辑页面，通常是本目录最需要审查的区域。
- `linkage-edit/modules/edit-premise.vue` 管理触发条件/前提条件，涉及设备指标、配置指标、比较条件、时间条件等组合。
- `linkage-edit/modules/edit-action.vue` 管理执行动作，涉及设备命令、场景动作或其他后端支持的动作类型。
- 各子目录下的 `__tests__/` 覆盖入口页面和关键模块，修改表单转换逻辑时应优先查看并补充这些测试。

## 运行与维护注意事项

- 自动化页面的表单字段应与后端规则模型保持一致，新增字段时要确认保存、编辑回显、复制/再次编辑和启停后的展示都能理解该字段。
- 条件编辑组件容易积累隐式 `any` 和散落的字段转换，维护时应避免在模板事件里直接写复杂 payload 组装逻辑。
- 设备指标、配置指标和动作目标通常依赖异步选项加载；审查时要确认加载失败、空列表、切换设备后旧值清理等状态。
- 删除、启用、停用和保存规则都应有用户可见反馈；不要只依赖接口成功而不刷新列表或同步本地状态。
- 本目录适合做局部静态检查和目标 Vitest 维护；不要为了验证一个表单映射改动而启动 broad E2E 或全量构建。

## 代码审查与重构建议

- 审查时优先比较“编辑已有规则”和“新建规则”的数据路径，确保同一规则模型不会在两个路径里产生不同字段。
- 把条件和动作的 payload 生成抽到纯 helper，输入 UI 表单状态、输出后端契约对象，这样更容易为边界条件补单元测试。
- 对 `edit-premise.vue` 这类高复杂度组件，推荐先记录字段含义和状态流，再拆出设备选择、指标选择、比较条件和时间条件 composable。
- 保持启停/删除/保存行为的幂等性审查：重复点击、接口失败、列表刷新失败和编辑页返回都应有明确处理。
- 如果新增自动化能力，建议同步更新子目录 README、相关测试说明和服务层契约说明，避免维护者只在页面里发现隐式规则。
