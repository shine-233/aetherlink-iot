# 设备详情公共展示模块

## 目录职责

`frontend/src/views/device/details/modules/public` 保存设备详情页中偏公共展示性质的子模块，例如地图点位与分布/表格组合展示。

## 文件关系

- `tencent-map.vue`
  - 负责经纬度解析、地图 SDK 装载、点位落图与异常坐标降级展示。
- `distribution-and-table.vue`
  - 统一承接设备详情中的分布视图、表格列表、命令/属性下发弹窗与期望消息登记链路。
- `__tests__`
  - 保存依赖外部 SDK 或图表场景下的展示测试。

## 静态审查建议

- 问题：地图 SDK、图表展示和表格口径一旦漂移，用户通常只会看到“数据不一致”，排障并不直观。
- 问题：`distribution-and-table.vue` 同时承载查询、弹窗、命令构造、属性载荷拼装和期望消息分流，单文件职责已经偏重。
- 问题：`tencent-map.vue` 这类地图组件通常还会叠加第三方 SDK 生命周期和坐标容错，如果没有把空坐标、非法坐标和 SDK 失败写清楚，后续接手会很吃力。
- 问题：`tencent-map.vue` 当前“清空定位”不会主动清掉旧 marker，目录级文档需要明确这是现状而不是遗漏，以免维护者误判。
- 改进：继续在文件头和 README 中写清数据来源、空值处理、加载失败降级策略，以及“查询 -> 打开弹窗 -> 载荷拼装 -> 提交 -> 刷新”的公共交互链路。
- 改进：后续优先把 `distribution-and-table.vue` 里的载荷构造、JSON 校验和接口契约整理成 helper 或 composable，降低页面脚本膨胀速度。
- 改进：后续把地图 SDK 加载、中心点计算和 marker 更新拆成更清晰的辅助层，降低 `renderMap` 聚合职责过多带来的维护成本。
- 建议实施步骤：先完成 `tencent-map.vue` 的中文文件头与关键 watch/初始化逻辑说明，再补公共目录级别的错误源说明。
- 建议实施步骤：随后识别公共展示模块里可共享的空态、失败态和数据口径处理规则，沉淀成统一说明。
- 预期效果：公共展示模块更容易审查，也更方便后续补充降级、空态验证与交互一致性治理。
