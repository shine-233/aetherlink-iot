# 遥测低层子组件

## 目录职责

`frontend/src/views/device/details/modules/telemetry/modules` 保存遥测总面板下的低层组件，负责趋势图、历史表格、聚合选择和图表渲染等细分能力。

## 文件关系

- `time-series-data.vue`
  - 负责时间范围、聚合窗口、聚合函数、统计值与趋势图的统一查询入口。
- `history-data.vue`
  - 负责单个遥测字段的历史表格、日期范围过滤与导出下载。
- `ChartComponent.vue`
  - 图表渲染包装层，承接 ECharts 实例生命周期和 option 同步。
- `AggregationSelector.vue`
  - 聚合条件选择器，约束聚合粒度与统计函数联动。
- `__tests__`
  - 保存这些子组件的测试资源。

## 静态审查建议

- 问题：时间范围、聚合窗口、下载路径和图表销毁逻辑都容易出现“静态看没问题、运行时才出错”的情况。
- 问题：`time-series-data.vue` 当前同时承担查询参数归一化、统计值汇总、图表数据映射和导出复用，watch 内职责较多。
- 问题：`history-data.vue` 把分页状态、日期范围和导出请求都放在一个入口里，如果参数双写没有注释兜底，后续修改很容易漏掉。
- 问题：`AggregationSelector.vue` 通过索引权重控制聚合粒度禁用态，新增选项时存在“顺序一变全局逻辑就偏”的隐性风险。
- 问题：`ChartComponent.vue` 当前用深度 watch + 浅合并更新 ECharts 配置，复杂 option 下可能同时遇到性能压力与旧配置残留。
- 改进：继续把时间范围、聚合参数、空数据处理和导出路径拼装写清楚，并逐步收敛到更易验证的 helper 或纯函数。
- 改进：后续优先把 `AggregationSelector.vue` 与 `ChartComponent.vue` 的 props 契约、事件输出和实例生命周期说明补齐，建立更完整的低层组件边界。
- 改进：后续把聚合权重映射从“索引约定”升级为更显式的规则映射，并评估图表组件是否需要更细粒度的 option 更新策略。
- 建议实施步骤：先完成遥测低层剩余组件的中文文件头和关键注释，再识别公共的聚合约束和图表映射逻辑。
- 建议实施步骤：随后把查询参数构造、图表 series 映射和下载地址生成逐步抽离，减少页面与图表层耦合。
- 预期效果：遥测子组件层更容易单独审查，也更方便后续统一验证展示、导出和图表渲染链路。
