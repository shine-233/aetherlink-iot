# 设备服务详情页

## 目录职责

`frontend/src/views/device/service-details` 负责设备接入服务点的详情管理页面，主要承载服务接入点列表、配置弹窗、删除入口以及跳转到设备管理页继续查看设备的链路。

这个目录虽然体量不大，但它直接连接“服务接入点配置”和“设备管理列表入口”，属于接入链路里的业务跳板页。

## 文件关系

- `index.vue`
  - 本目录主页面，负责读取路由中的服务插件与服务标识，拉取服务接入点列表，并提供查看设备、修改配置、删除等操作。
- `components/serviceModal.vue`
  - 承载服务接入点配置修改弹窗。
- `components/serviceConfigModal.vue`
  - 承载服务配置相关的辅助弹窗或详情展示。
- `../manage/index.vue`
  - 当用户点击“查看设备”时，会带着 `service_identifier` 和 `service_access_id` 跳转过去继续查看对应设备列表。

## 当前状态流

1. 页面从路由读取 `id`、`service_identifier` 等参数。
2. `getList` 根据 `service_plugin_id` 拉取服务接入点分页数据。
3. 列表操作分成三类：
   - 查看设备：跳转到设备管理页并携带服务筛选参数。
   - 修改配置：打开服务配置弹窗。
   - 删除：调用删除接口后重新刷新列表。

## 静态审查建议

### 发现的问题

- `index.vue` 目前仍以页面脚本直接承接路由解析、分页状态、表格列定义和跳转逻辑，后续一旦再加筛选、权限态或批量操作，很容易继续膨胀。
- “查看设备”跳转依赖多个 query 参数拼装，属于前后页面之间的重要契约，但当前目录级说明还不够明确。
- README 之前偏模板化，无法帮助维护者快速看懂它在设备接入链路中的位置。

### 改进方案

- 将分页查询参数、跳转参数拼装、删除后刷新等逻辑逐步抽成局部 helper 或 composable。
- 在 `index.vue` 文件头和本 README 中持续记录“路由入参 -> 列表 -> 跳转设备管理”的状态流。
- 若后续继续扩展服务接入点能力，优先拆分表格动作和弹窗打开逻辑，避免全部堆在页面壳层。

### 建议实施步骤

1. 先继续补 `index.vue` 的中文文件头和关键函数说明。
2. 再抽出服务详情页专用的 query/helper，统一处理分页和跳转参数。
3. 若未来增加更多弹窗或列表动作，再把表格 action render 进一步下沉。

### 预期效果

- 维护者能更快理解服务详情页在设备接入链路中的作用。
- 页面跳转契约更清楚，后续修改服务接入点或设备管理筛选逻辑时更容易局部审查。
- GitHub 浏览者即使不先读源码，也能从 README 把结构和风险点看明白。
