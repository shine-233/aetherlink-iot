# gen-plugin 插件生成器

## 目录定位

这个目录实现 `gmqctl gen plugin`，用于给 GMQTT broker 插件开发生成一组可继续手写完善的 Go 模板文件。

## 文件用途

- `command.go`：定义 CLI 参数、输出目录准备、文件创建保护和生成流程。
- `tmpl.go`：保存主插件、hook 包装器、配置结构体的模板，并负责模板渲染和 `go/format`。
- `command_test.go`：覆盖生成文件、可选配置文件和 hook 名称校验。

## 生成物、示例、测试数据边界

生成物不会写回本目录，默认写到 `-o/--output` 指定目录；测试运行时会临时创建并删除 `./testdata/`。生成出的 `.go` 文件是插件开发脚手架，不等同于可直接投产的业务插件。

## 审查发现

- 文件覆盖保护已存在，生成器不会静默覆盖同名文件。
- 生成流程依赖包级全局变量，测试之间需要小心重置状态。
- 模板里包含 `panic("implement me")` 这类占位实现，README 需要明确这是脚手架边界。

## 重构建议

- 将命令参数整理成 `Options` 结构体，让 `run` 接收显式参数，减少全局状态。
- 增加 golden 文件测试，锁定生成代码格式和 hook 包装器结构。
- 后续可把模板移到独立 `.tmpl` 文件或 `embed` 资源，降低长字符串维护成本。

## 验证建议

- 修改生成器后运行：`go test ./cmd/gmqctl/command/gen-plugin -count=1`。
- 修改模板后建议额外手动生成一个示例插件，再运行 `go test` 或 `go test ./...` 验证生成代码可编译。
