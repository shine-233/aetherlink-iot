## 六、维护规则

1. 能力规划结论以 ROADMAP 为唯一入口；历史决策记录保存在维护者私有环境。
2. 新增文档同步登记到本图；文档失效时移入对应 `archive/` 并在本图注明，不在原位留空壳。
3. `verification/` 仅保留运行时证据。**不要**把旧 run 目录嵌套进 `archive/<YYYY-MM>/`：
   `coverage_inspector.js` 的 `listArchiveDirectories()` 只读一层，嵌套会让 legacy manifest
   从"被发现并判为 legacy"变成"根本没被发现"，属于静默改变度量行为。要清理旧产物，
   应直接删除（先确认已有等价更新证据）或整体移出仓库，而不是在目录内再套一层。
4. 移动根目录文档前，先确认是否被 `deploy/package.sh`、`deploy/package.ps1` 或相对链接引用。
5. 状态只能写 done / partial / pending；禁止用单测绿、路由可访问、覆盖率数字或页面截图单独宣称完成。
